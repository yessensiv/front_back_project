1. Файлы и запуск

Открой todo/index.html в современном браузере. Для получения данных нужен интернет. У приложения нет собственного сервера: JavaScript обращается непосредственно к DummyJSON. Node.js и jsdom используются только для автоматических тестов.

2. HTML: теги и атрибуты

HTML описывает структуру. В JavaScript используются функции, выражения и события — «тегами JavaScript» их обычно не называют. Тег <script> лишь подключает или содержит JavaScript.

ТегНазначение в приложении
<html lang="ru">Корень документа; язык помогает браузеру и программам чтения с экрана.
<head>, <meta>, <title>Настройки страницы: UTF-8 для кириллицы, viewport для телефона, заголовок вкладки.
<link>, <script>Подключают стили и код.
<body>, <main>, <header>Видимая часть, основное содержимое и заголовок приложения.
<section>, <h1>–<h3>Смысловые разделы и заголовки: информация о пользователе, его задачи.
<div>, <span>, <p>, <small>Группировка, текст задачи, сообщения и примечание о локальной задаче.
<ul>, <li>Список задач и одна строка списка.
<template>Невидимый образец строки. Код клонирует его для каждой задачи.
<button>Добавление, изменение, удаление, закрытие, ник исполнителя и переключение темы.
<form>, <label>Форма задачи и подписи полей. for у label соответствует id поля.
<input type="text">Название задачи; required запрещает пустое значение, maxlength="200" ограничивает длину.
<input type="search">Поиск по названию в главном списке.
<input type="checkbox">Галочка. Состояние читается из checked, а не из value.
<select>, <option>Исполнитель, направление сортировки и статус в профиле. Видимый текст option и его value могут отличаться.
<dialog>Модальное окно. showModal() открывает его поверх страницы; close() закрывает.
<img>Аватар. src берётся из пользователя; маленькая картинка имеет пустой alt, поскольку рядом уже указан ник.
<dl>, <dt>, <dd>Список пар «поле — значение»: Email, телефон, компания и другие сведения.
<details>, <summary>Раскрывающийся справочник в конце главной страницы.
<a>, <code>Ссылки и обозначение фрагментов кода в справочнике.

Атрибуты, которые связывают HTML и код

  • id — уникальный адрес элемента, например profile-sort. class — общая группа для оформления и поиска нескольких элементов.
  • data-action="edit" хранит действие кнопки, а data-key="server-1" — ключ строки. JavaScript читает их через dataset.action и dataset.key.
  • type="submit" отправляет форму. Остальные кнопки имеют type="button", чтобы не отправить её случайно.
  • hidden скрывает элемент; disabled блокирует действие на время запроса; autofocus задаёт первоначальное поле ввода.
  • aria-label даёт элементу понятное имя. aria-labelledby связывает диалог с заголовком. aria-controls указывает список, которым управляет фильтр.
  • role="status" и aria-live="polite" позволяют озвучивать изменения. aria-pressed обозначает выбранную кнопку, aria-busy — загрузку списка.

3. Данные и связь с исполнителем

Пример объекта задачи ниже учебный: значения показывают структуру и не привязаны к текущему набору API.

const task = {
  id: 1,
  todo: "Подготовить презентацию",
  completed: false,
  userId: 26
};

id — идентификатор задачи. todo — её название. completed — логическое значение статуса. userId — идентификатор назначенного исполнителя. Это не обязательно ID человека, который уже выполнил задачу: невыполненная задача тоже имеет исполнителя.

users = new Map(results[1].value.map(user => [Number(user.id), user]));
const user = users.get(Number(todo.userId));

Map хранит пары «ID → объект пользователя». Сначала числовые ID становятся ключами, затем по todo.userId находятся username, image, имя и остальные сведения. Number() нужен, поскольку значение из select является строкой.

ПеременнаяЧто хранит

activeFilter / activeSortСтатус и сортировка главного списка.

4. API.js: HTTP-запросы

REST API принимает HTTP-запрос и возвращает JSON. todoApi — наш объект с методами для обращения к нему. Таблица отражает запросы именно этой реализации.

Метод кодаHTTP и адрес относительно https://dummyjson.comДействие
getAll()GET /todos?limit=0Загрузить задачи.
getAll("asc")GET /todos?limit=0&sortBy=todo&order=ascПолучить задачи по возрастанию названия; desc меняет направление.
getUsers()GET /users?limit=0Загрузить исполнителей.
create(task)POST /todos/addПередать название, статус и userId.
update(id, changes)PATCH /todos/{id}Изменить поля исходной задачи.
remove(id)DELETE /todos/{id}Запросить удаление исходной задачи.

limit=0 запрашивает весь набор; sortBy=todo задаёт поле сортировки. Эти параметры и методы описаны в документации Todos; получение пользователей — в документации Users.

Общий помощник requestTodo

async function requestTodo(url, options) {
  const response = await fetch(url, {
    ...options,
    signal: AbortSignal.timeout(15000)
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

fetch() начинает запрос, await ожидает результат, не блокируя весь интерфейс. Тайм-аут ограничивает ожидание. HTTP-ошибка сама по себе не обязана отклонить Promise fetch, поэтому отдельно проверяется response.ok. response.json() преобразует тело ответа в JavaScript-объект и тоже возвращает Promise.

body: JSON.stringify(task),
headers: { "Content-Type": "application/json" }

У POST/PATCH body содержит строку JSON, а заголовок объясняет серверу её формат. GET передаёт параметры в адресе через URLSearchParams. Обёртка (() => { ... })() изолирует внутренние переменные API.js, а window.todoApi делает нужные методы доступными следующему скрипту. Object.freeze() запрещает заменять свойства этого объекта.

5. Как появляется строка задачи

  1. renderTodos() получает актуальные задачи, применяет поиск и статус главного списка.
  2. renderList() копирует todo-item-template через cloneNode(true).
  3. Заполняет название, статус, ник и картинку; записывает ключ в item.dataset.key.
  4. Собирает строки в DocumentFragment и заменяет содержимое списка через replaceChildren().
<div class="todo-content">
  <span class="todo-text"></span>
  <button class="todo-user" type="button" data-action="profile">
    <img class="user-avatar" alt="">
    <span class="user-handle"></span>
  </button>
  <span class="task-state"></span>
</div>

Название и кнопка пользователя — отдельные элементы внутри .todo-content с display: grid. Каждый занимает свою строку. Поэтому длинное название переносится, а ник остаётся под ним. min-width: 0 разрешает сжимать колонку, overflow-wrap: anywhere переносит даже очень длинное слово.

Название присваивается через textContent: введённый текст <img ...> остаётся текстом и не превращается в HTML. Класс completed добавляет зачёркивание и зелёный статус. setAvatar() скрывает изображение, если адрес отсутствует или загрузка картинки завершилась ошибкой.

В профиле применяется тот же шаблон и renderList(..., false): кнопка ника скрыта, потому что пользователь уже находится в собственной карточке. Изменение, удаление и галочка остаются.

В документации Todos нет отдельного фильтра по completed. Поэтому профиль делает настоящий GET, но не отправляет выдуманный параметр фильтрации. todoApi.getAll(order) получает отсортированные задачи, а getProfileTodos() и renderProfileTasks() оставляют нужного исполнителя и статус. Это ограничение выбранного API, а не отсутствие запроса. Описание возможностей Todos.

Путь действия в профиле

change у profile-filter или profile-sort
  → fetchProfileTodos()
  → todoApi.getAll(order)
  → GET /todos?limit=0&sortBy=todo&order=asc
  → profileServerTodos = result
  → mergeTodoChanges(profileServerTodos, profileSort)
  → отбор по userId
  → отбор по completed
  → renderList(profile-todos, visible, false)

Отдельные переменные профиля позволяют менять его порядок, не переставляя главный список. Счётчик показывает число видимых задач и общее количество у исполнителя; числа выполненных и невыполненных относятся ко всем его задачам, до фильтра.

Почему запоздавший ответ не ломает список

const request = ++profileRequest;
const userId = profileUserId;
const result = await todoApi.getAll(order);
if (request !== profileRequest ||
    userId !== profileUserId || !profileDialog.open) return;

Если быстро выбрать А–Я, затем Я–А, первый ответ может прийти последним. Сравнение номера оставляет только актуальный результат. Проверка пользователя и открытого диалога защищает при закрытии или переходе в другой профиль. Сам сетевой запрос при этом не обязательно прерывается — его устаревший результат игнорируется.

При ошибке старый список остаётся, select возвращаются к последним применённым значениям, появляется кнопка повторной загрузки. Пока идёт запрос, сообщение и aria-busy показывают ожидание. Повторная загрузка использует текущие, восстановленные настройки.

7. CRUD: что происходит при каждом действии

CRUD — Create, Read, Update, Delete: создать, прочитать, изменить, удалить.

Добавление

  1. Кнопка «Добавить» вызывает openTodoForm(). В профиле в неё передаётся текущий исполнитель.
  2. Форма сбрасывается; editingTodoKey = null; вызывается showModal().
  3. Событие submit вызывает preventDefault(), чтобы браузер не перезагрузил страницу.
  4. Название очищается через trim(), ID превращается в число, статус читается из checkbox.checked.
  5. Если название состоит из пробелов, setCustomValidity() и reportValidity() показывают ошибку. Также проверяется существование исполнителя в Map.
  6. Кнопки блокируются, отправляется POST. После успеха задача получает уникальный localKey, попадает в todoChanges.created, сохраняется и показывается в списках, если подходит под выбранные фильтры.

Редактирование

openTodoForm(todo) запоминает ключ и заполняет ту же форму прежними значениями. После submit вызывается mutateTodo(todo, task). Можно изменить название, исполнителя и статус. При смене исполнителя задача исчезает из старого профиля, потому что её новый userId больше не совпадает с profileUserId.

Галочка

mutateTodo(todo, { completed: event.target.checked });

Для исходной задачи отправляется PATCH. После подтверждения обновляются надпись, зачёркивание и оба списка. Если выбран фильтр «Не выполнено», завершённая задача исчезает из результатов. При ошибке данные не меняются: повторная отрисовка возвращает прежнее положение галочки.

Удаление

mutateTodo(todo, null) означает удаление. У исходной задачи отправляется DELETE и сохраняется её ID в deleted. Локальная задача удаляется из массива created. После успешной операции список перерисовывается, включая открытую карточку пользователя.

Отмена и ошибки

Кнопка «Отмена» справа закрывает диалог, не сохраняя введённые поля. Подтверждение с галочкой находится слева. Во время сохранения элементы формы заблокированы; Escape не закрывает окно, пока операция не завершится. Если сохранение не удалось, диалог остаётся открытым с введённым текстом и сообщением об ошибке; finally возвращает доступность кнопок.

8. Почему нужен localStorage

DummyJSON подтверждает POST/PATCH/DELETE, но не сохраняет эти операции на сервере. Поэтому приложение хранит изменения в браузере. Это описано в разделах добавления, изменения и удаления в документации API.

todoChanges = {
  created: [], // новые задачи с localKey
  updated: {}, // изменения исходных задач по ID
  deleted: []  // ID скрытых исходных задач
};

mergeTodoChanges(source, order) работает по следующему правилу:

актуальные задачи =
  новые локальные задачи
  + задачи ответа API без deleted
  + поверх каждой исходной задачи поля из updated[id]

Например, { ...todo, ...todoChanges.updated[todo.id] } сначала копирует серверную задачу, затем заменяет изменённые поля. ID удалённых задач превращаются в Set, чтобы проверять их через has(). Оба списка используют одну функцию объединения, поэтому новый GET не отменяет редактирование и не возвращает удалённую задачу.

Сервер ничего не знает о новых локальных названиях. Если выбрана сортировка и есть такие названия, после ответа выполняется дополнительный localeCompare(): локальные задачи встраиваются в общий алфавитный порядок. Сам запрос сортировки всё равно отправляется.

Ключ хранилища — front_back_project.todos.v1. JSON.stringify() превращает данные в строку при записи, JSON.parse() восстанавливает их при запуске. Старый формат сохранений остаётся совместимым.

Новые задачи имеют отдельный localKey, потому что демонстрационный API может возвращать один и тот же ID при нескольких добавлениях. Редактировать и удалять такие задачи на сервере нельзя надёжно: их там нет. Эти операции выполняются локально; PATCH/DELETE отправляются для исходных задач.

Если хранилище недоступно, приложение продолжает работать в текущем открытии и сообщает, что сохранить изменение для следующего запуска не удалось. Данные не синхронизируются между браузерами и компьютерами. Для file: поведение хранения зависит от браузера; для предсказуемого хранения можно использовать статический просмотр через HTTP.

10. JavaScript: конструкции и события

  • const запрещает переприсваивание переменной, но не делает содержимое объекта неизменяемым. let используется для состояния, которому присваиваются новые значения.
  • async / await помогают последовательно описать асинхронную операцию. try / catch / finally разделяют успех, ошибку и обязательное завершение.
  • Promise.allSettled() ждёт задачи и пользователей; каждый результат содержит status и value либо reason. Ошибка загрузки пользователей не уничтожает успешно загруженные задачи.
  • map() преобразует элементы, filter() отбирает, find() находит один объект, some() проверяет наличие подходящего элемента, forEach() выполняет действие для каждого.
  • sort() меняет порядок массива. Поэтому перед сортировкой запасного списка профиля создаётся копия [...serverTodos].
  • ?. безопасно обращается к необязательному полю, например user.company?.name. ?? подставляет запасное значение только для null/undefined.
  • условие ? значение1 : значение2 — условное выражение. Оно выбирает, например, подпись «Выполнено» или «Не выполнено».
  • ...object копирует свойства, ...array раскрывает элементы. В Object.assign() новые свойства записываются в существующий объект.
  • Шаблонные строки в обратных кавычках вставляют переменные через ${...}: адрес задачи, сообщения и счётчики.

Делегирование событий

const button = event.target.closest("button[data-action]");
const row = event.target.closest(".todo-item");
const key = row?.dataset.key;

Обработчик установлен на список, а не на каждую кнопку. Событие всплывает от нажатого элемента. closest() находит кнопку и строку даже при клике по картинке или тексту внутри кнопки. После replaceChildren() строки новые, но обработчик списка остаётся.

11. CSS и тема

  • :root задаёт переменные цветов, например --surface. Правило :root[data-theme="light"] заменяет их для светлой темы.
  • display: flex располагает галочку, содержимое и кнопки строки; gap задаёт промежуток.
  • display: grid строит колонки поиска, две части профиля и отдельные строки содержимого задачи.
  • minmax(0, 1fr) создаёт гибкие колонки профиля; нулевой минимум помогает длинному тексту не растянуть окно.
  • .modal::backdrop затемняет фон. max-height и overflow: auto разрешают прокрутку большого профиля.
  • body:has(dialog[open]) запрещает прокрутку страницы позади открытого окна.
  • .modal-actions с justify-content: space-between разводит подтверждение и отмену по краям.
  • @media (max-width: 640px) перестраивает две колонки в одну и уменьшает отступы.
  • :hover показывает реакцию на наведение; :focus-visible выделяет элемент при управлении клавиатурой.

theme.js читает ключ front_back_project.todos.theme и записывает тему в document.documentElement.dataset.theme. CSS реагирует на этот атрибут. По нажатию меняется тема и её сохранённое значение. Это отдельное сохранение: переключение цветов не влияет на задачи.

12. Как проверить и объяснить работу

Сетевые запросы в браузере

  1. Открой страницу задач и инструменты разработчика, вкладку Network → Fetch/XHR.
  2. Нажми ник: появится GET списка задач для профиля.
  3. Выбери в профиле «Выполнено»: появится новый GET. В адресе может не быть нового параметра статуса — он применяется в коде после ответа.
  4. Выбери Я–А: в запросе будут sortBy=todo и order=desc.
  5. Измени исходную задачу: проверь PATCH и JSON в Request Payload. Удали исходную задачу: проверь DELETE.
  6. Добавь задачу: проверь POST с todo, completed и userId. Её последующие изменения локальны.
  7. Обнови страницу: сохранённые изменения должны снова наложиться на исходный ответ.

Автотесты

Из корня проекта в терминале Windows:

npm.cmd install --no-save --package-lock=false jsdom
node todo/tests.cjs

Тесты проверяют CRUD, выбор исполнителя, профиль, поиск, отдельные сортировки, запрос при фильтрации профиля, счётчики, ошибки и повтор, запоздавшие ответы, переключение профиля и сохранения. Запросы в этих тестах подменены предсказуемыми ответами: это проверка логики, а не доступности внешнего сервиса. jsdom не проверяет реальное расположение пикселей, загрузку аватаров и поведение модальных окон конкретного браузера; диалоги в тесте имитируются.

Частые вопросы

Зачем два ID?
todo.id определяет задачу; todo.userId определяет исполнителя.
Почему ник снизу?
Название и кнопка ника — отдельные строки grid-контейнера.
Где находится backend?
Собственного backend нет. Удалённым источником данных служит DummyJSON.
Фильтр и сортировка?
Фильтр убирает неподходящие элементы; сортировка меняет порядок оставшихся.
Почему GET повторяется?
Каждое переключение профиля перечитывает данные по требованию интерфейса, даже если статус затем отбирается в браузере.
Зачем localKey?
Новые демонстрационные задачи могут иметь повторяющийся серверный ID; локальный ключ различает их в интерфейсе.
Почему PATCH не меняет API навсегда?
DummyJSON имитирует запись. Приложение хранит подтверждённые изменения отдельно в localStorage.
Что при ошибке?
Показывается сообщение, старые данные остаются, кнопки снова доступны, загрузку можно повторить.

Для объяснения на защите: «HTML задаёт элементы, CSS отвечает за их расположение, API.js отправляет запросы, script.js связывает действия с данными. Задачи связаны с пользователями через userId. Два списка имеют свои фильтры, но используют общие локальные изменения и одинаковые CRUD-обработчики».
